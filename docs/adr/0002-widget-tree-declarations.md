# Render widget-tree declarations through the public plugin API

Plugins emit row, column, label, leader, spacer and list data; each client renderer draws it under core-defined semantics. Stock sidebar and tab-strip visuals use the same public API as other plugins, without privileged rendering. References to existing pane Surfaces are renderer-neutral; plugin-supplied cell-grid regions are outside this spike. See ADR 0005 for the approved rendering-ownership clarification.

Accepted by Tommy on 2026-10-10; source: Kizn design record, revision 3. Number allocated in this new repository with no remotes or default branch; recheck against the remote default branch before the first PR.

Task 3.2 implements the six node kinds through the same public nested declaration path. Core flow semantics make rows horizontal and columns/lists vertical; list entries retain producer order without implicit markers or gaps. Empty containers have no intrinsic extent. Labels carry declared text and roles. A leader is elastic inline content between its neighbors, not a vertically expanding region. A spacer declares empty logical spacing (`size`, including zero) along its containing flow, with no text or cross-axis demand. The terminal client maps logical spacing to terminal units and measures/clips text in its renderer; declarations carry no terminal coordinates or fixed cell rectangles. Stock UI explicitly declares its empty tab-strip spacing instead of depending on empty-row allocation.

Task 3.3 adds Footer and FooterRight to the public Zone vocabulary and optional named Tone values on Labels and Leaders (`bg-lime`, `fg-cyan`). Tone selects only a client-palette background or foreground; Role continues to determine the other styling, and an absent Tone preserves the role/default focused-row palette. The terminal client allocates each footer slot one row and clips excess nested content; FooterRight aligns nonelastic placement content to the slot’s right edge, while elastic Leaders fill the slot. List placements remain vertically allocated in producer order. A declaration may place at most one tree in each of the three zones. Plugin-supplied pixels, terminal rectangles and literal RGB colors are not accepted.

Sidebar menus are optional Row.menu Column trees or public named Use references, not a separate native menu vocabulary. Agent-tree preserves sectioned-flat list ordering, gaps and palette roles. Stock and agent-tree declare only Use references (sidebar.space-menu:<workspace_id>, sidebar.tab-menu:<tab_id>, sidebar.session-menu); the independently watched sidebar-menus plugin owns those fragments' labels/actions/exact contexts. Its space menu declares immediate scoped New tab and Rename without a redundant SPACE heading; tab menus declare danger Close tab; pane rows have no menu. A blank Footer row references the session fragment with a muted SESSION heading, New space and Detach from session. Stock provides the same footer and list-reference fallbacks, replacing always-visible New space/New tab/Menu controls. Stock composition priority 10 still wins over agent-tree priority 0 while consuming its List/Footer placements. Any plugin can replace or compose named fragments using public priority and Use, with no privileged menu plugin ID. Rename is declared via when rename_space, Input and host:create/cancel; generic host:new producers may retain the new_tab name form. Focus-transition expansion persists through the existing collapsed-state writer: a newly focused tab reveals its collapsed destination, but initial publication, periodic updates and unchanged focus preserve manual collapse.
