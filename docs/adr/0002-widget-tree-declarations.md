# Render widget-tree declarations through the public plugin API

Plugins emit row, column, label, leader, spacer and list data; each client renderer draws it under core-defined semantics. Stock sidebar and tab-strip visuals use the same public API as other plugins, without privileged rendering. References to existing pane Surfaces are renderer-neutral; plugin-supplied cell-grid regions are outside this spike. See ADR 0005 for the approved rendering-ownership clarification.

Accepted by Tommy on 2026-10-10; source: Kizn design record, revision 3. Number allocated in this new repository with no remotes or default branch; recheck against the remote default branch before the first PR.

Task 3.2 implements the six node kinds through the same public nested declaration path. Core flow semantics make rows horizontal and columns/lists vertical; list entries retain producer order without implicit markers or gaps. Empty containers have no intrinsic extent. Labels carry declared text and roles. A leader is elastic inline content between its neighbors, not a vertically expanding region. A spacer declares empty logical spacing (`size`, including zero) along its containing flow, with no text or cross-axis demand. The terminal client maps logical spacing to terminal units and measures/clips text in its renderer; declarations carry no terminal coordinates or fixed cell rectangles. Stock UI explicitly declares its empty tab-strip spacing instead of depending on an implicit empty-row gap.
