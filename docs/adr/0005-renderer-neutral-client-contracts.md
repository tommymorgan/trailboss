# Keep shared client contracts independent of the renderer

Tommy approved renderer-neutral shared contracts as a requirement of this spike on 2026-10-10, to preserve future GUI and web clients without implementing them now. The shared Core owns session state and action semantics; each client owns its renderer, pixels and mapping of Zones to geometry. Shared widget declarations carry structure, actions and semantic styling, and shared Surface data carries terminal state. Do not expose ratatui types, terminal escape sequences or fixed terminal-cell geometry as widget-layout requirements in shared contracts. A Surface remains a cell grid; that inherent terminal geometry is not a TUI chrome/layout contract.

Keep the accepted coarse vendored runtime, including internal ratatui data types, behind a client-neutral adapter. The terminal renderer consumes the shared contracts instead of defining them. Public declarations determine app UI composition, including where existing pane Surfaces are placed; a reference to a runtime-owned Surface is not a plugin-rendered cell-grid region. Producers run outside browser clients; do not require a client to spawn Bun or accept producer stdin directly.

A future browser transport adapter can preserve session API semantics while using a browser-compatible connection. Browser transport/authentication and GUI toolkits remain unselected and outside this spike. No bridge service, GUI client, web client, multi-client synchronization policy or additional dependency is introduced by this decision.

Source: Kizn design revision 6 and glossary revision 4. Number allocated in the new repository with no remote default branch; recheck before the first PR.

## Generation-1 wire contract (Task 3.5)

An independent local consumer connects to the named session’s `trailboss-client.sock`; the unchanged newline-JSON session API remains on `trailboss.sock`. No renderer library is required. The executable contract probe is `python3 tests/support/neutral_consumer.py CLIENT_SOCKET UNFOCUSED_TAB_ID OUTPUT_JSON`. It uses only Python’s standard library and invokes an action found in the actual producer declaration, rather than constructing a client projection or importing the Rust codec. Its plain-PTY probe deliberately does not negotiate optional delta/reuse/scroll encodings or render graphics/popups.

Each message has a four-byte little-endian payload length, followed by bincode 2 standard encoding (little-endian variable integers). Normal frames are bounded to 2 MiB. Unsigned values below 251 are one byte; prefixes 251/252/253 carry u16/u32/u64. Strings are an unsigned byte count followed by UTF-8, vectors an element count then their elements, booleans and Option tags are one byte (0/1), and enums carry an unsigned variant index. Frozen generation-1 tags relevant here:

| Direction | Tag | Fields in order |
| --- | --- | --- |
| client → Core | 20 | control kind string, JSON data string |
| client → Core | 15 | Core boot ID string, original session API request JSON string |
| Core → client | 20 | control kind string, JSON data string |
| Core → client | 13 | complete pane Surface below |
| Core → client | 18 | boot ID string, request ID string, final-chunk bool, byte vector |

Start with `endpoint.hello.v1`: generation 1, zero cell pixel sizes, `surface_size: {cols, rows}`, false pixel_mouse/direct_graphics/endpoint_keybindings/mouse_capture, true surface_active, false surface_reuse/surface_delta/surface_scroll, and codec arrays containing `shell.snapshot.v1`, `shell.surface.v1`, `shell.input.semantic.v1`, `shell.blob.v1`. `endpoint.welcome.v1` reports negotiated codecs and capabilities. Ignore unrecognized named controls, not binary field layouts. `shell.snapshot.v1` contains boot_id, revision, focused_workspace_id, focused_tab_id, focused_pane_id and session resources. `endpoint.plugin-ui.v1` contains boot_id, revision and ui items with plugin_id, ui_id, surface, and optional declaration; pair revisions with the snapshot.

Declarations are `{herdr:"widget_tree", version:1, zones:[{zone,tree}], composition?:{priority,tree}}`. The original wire key remains unchanged by Trailboss product branding. Zones are list/footer/footer_right. Nodes use type: column/row children; label text/role/optional tone; leader optional tone; spacer logical size; list entries; flex relative weight/child; surface (runtime-owned focused pane reference); zone zone/optional fallback; when condition/child; input (Core-owned editable text). Conditions are no_pane, has_pane, new_tab and rename_space. Rows may carry action, context with workspace_id/tab_id/pane_id, and optional menu: an ordinary Column tree of public nodes. Menu content undergoes the same recursive validation, including action authorization, context identities, depth and child-count limits, as visible content. Clients own hover/focus triggers, popup geometry and dismissal; producers own every menu label and action. Tones are bg-lime/fg-cyan, not concrete colors. Roles are nonempty semantic names, not terminal control strings. Core rejects control characters in label text and role, unknown node fields (including pixel/cell rectangles), undeclared plugin actions, excessive nesting and malformed placement; it never sanitizes a malicious declaration into a different valid one.

Declarations additionally accept optional fragments:[{name,priority,tree}]. A use node (`{type:"use",name}`) resolves that name from any producer, in ordinary composition or Row.menu. The highest public priority wins; ties use lexicographic plugin ID, matching composition precedence. Names are nonempty, control-free, at most 200 characters; each declaration allows at most 128 fragments with unique names and recursively validated trees. Empty fragments are omitted. Fragment-only declarations use zones:[] and need no application composition. References do not bake in a plugin identity or a native slot enum; unresolved/cyclic references produce no content within the client's bounded traversal. Menu references resolve to ordinary Column content.

The independently watched tommymorgan.sidebar-menus plugin declares sidebar.space-menu:<workspace_id>, sidebar.tab-menu:<tab_id> and sidebar.session-menu. These names are producer conventions, not Core special cases. Stock and agent-tree only reference them through Use; they do not embed the menu labels or action rows. Another plugin can replace a complete named menu at a higher priority, or compose reusable fragments with Use. Reserved Core actions retain shared semantics while each resolved fragment's nonreserved actions retain its supplying producer's identity.

For producer actions, send the original `plugin.action.invoke` request on tag 15 using the received boot ID, an independent request ID, the received plugin_id/action_id and context plus invocation_source plugin_ui. Core validates and forwards the invocation, adds correlation, and reports the result on tag 18; session focus changes arrive through snapshots and Surfaces. Reserved actions are host:new (generic new-tab name prompt), host:new-space, host:new-tab (immediate tab.create in context.workspace_id with focus), host:rename-space (edit context.workspace_id), host:close-tab (close exact context.tab_id), host:detach, host:create, host:cancel and host:focus. These are Core-defined semantics, not producer handlers. Input is shared by new_tab and rename_space forms; host:create/cancel submits/cancels the current form. The retired tab_name node, menu condition and host:menu action are not aliases.

Context-free menu actions inherit their chosen scope: popup and nested command-palette entries inherit the nearest nonempty ancestor row context, falling back to the originating menu-bearing row. Explicit child contexts take precedence unchanged. Actionless Row.menu entries navigate native popup submenus; actionable entries retain invocation behavior. The native popup retains its root anchor and validates every chosen submenu against current provider/context/menu identities; disappearance dismisses it. This permits shared public Use confirmation fragments without repeating identities in every button. Close space in the ellipsis menu uses shared Cancel-first confirmation and the existing producer action, not a new reserved Core action. An untargeted host:focus selects the previous live tab; a targeted host:focus retains its exact-target semantics. MRU cycling is distinct, client-local navigation over a frozen order until the user finishes cycling.

Complete Surface fields are: boot_id string, projection_revision u64, surface_revision u64; FrameData; pane vector; split vector; optional popup; graphics scene. FrameData is a cell vector, width u16, height u16, optional cursor, hyperlink string vector, graphics byte vector. Each cell has symbol string, foreground u32, background u32, modifier u16, skip bool, optional hyperlink u32. Named colors are 0x00000000..0x00000010, indexed colors 0x010000II, RGB 0x02RRGGBB; modifier bit 0 is bold. Cursor is x/y u16, visible bool, shape byte (DECSCUSR 0..6). Cells are row-major and must total width × height.

A pane contains pane_id string, content_revision u64, outer and inner rectangles (x/y/width/height u16), optional scrollbar rectangle, optional scroll metrics (offset_from_bottom/max_offset_from_bottom/viewport_rows u64), focused/mouse_reporting/sgr_pixel_mouse/alternate_screen_active bools, pixel_width/pixel_height u32. Splits carry direction enum, pos u16, two rectangles and bool path vector; popup and graphics retain the existing runtime wire schema. The probe requires zero splits, no popup, and empty graphics assets/placements/retained_assets; it decodes and checks every field for this actual plain-PTY input. These rectangles and colors describe terminal state, never widget layout. The full retained field definitions are in `crates/trailboss-runtime/src/protocol/wire.rs`; no new schema, protocol tag, public API, dependency or transport is introduced.
